0 · The two cardinal rules read first

Everything below hangs off two architectural decisions. They are enforced in code, not just convention.

① The pipeline interprets — it never adjudicates.
The document pipeline is a pure function documents → (accurate episode JSON + non-blocking signals). Whether to hold / file / pay a claim lives in a separate decision layer. A whole-claim veto (canHarmonise, QUARANTINE, survivorIdentityCount) was tried and deliberately deleted — a grep across the harmoniser + v2 runState returns zero matches. When a wrong page leaks in, the fix is exclude the page + emit a signal, never block.
② "Re-run AI Analysis" = from scratch, always.
analyzeClaim({force:true}) calls resetClaimDerivedState before the run opens, wiping doc_phase_ledger → claim_harmonised_episodes → document_sections (one txn) and rebuilding from source docs. Full segment+classify+extract LLM cost is paid every time, by design; an "incremental refresh" was explicitly rejected. Accepted side-effect: human field-corrections orphan (section_id ON DELETE SET NULL).

Cost ceiling on top of both: CLAIM_HARD_LIMIT_INR = 15 per claim (soft warn at ₹10), enforced via per-call recordCall into llm_cost_log.

2 · Control plane — how a run is driven & healed

There is no central driver chaining the stages. analyzeClaim() fans jobs out; each Bull worker self-advances to the next queue; a derived run cursor aggregates progress and a gate decides when harmonisation may fire. A cron heals stalls.

Run cursor & gate. claim_ai_runs is a derived aggregator, not a driver — recomputeFromState recounts sections, runs a stall detector (ledger rows running > 300 s → failed) and an orphan re-enqueue, then flips the run to succeeded (all docs complete, none failed) or partial. The harmoniser only proceeds when docs_completed + docs_failed ≥ total_docs — failed docs count as "settled" to avoid deadlock.
Self-healing (CRIT-1). A June-2026 9-hour stall was traced to a lost terminal queue-fire. Fixes: an un-coalescable terminal harmonise job (harmonise:<id>:final), Fix-17 auto-heal re-enqueue inside recomputeFromState, and the claimRunReconciler cron. PASS2 (cheap heartbeat) is always-on (CLAIM_RUN_HEARTBEAT_ENABLED!=false); PASS1 (heavy Sonnet re-drive) is dormant behind CLAIM_RUN_RECONCILER_ENABLED.

Deployment note: API vs Worker is one image split by RUN_WORKERS. But analyzeClaim itself isn't gated — it can enqueue from either container; only the queue processors self-gate on RUN_WORKERS!=='false'.

4 · Harmonisation — one LLM call + a deterministic Fix-N chain Wave 7

CRIT-3 / B7 · fixed, uncommitted  Financial reconciliation (reconcileFinancials, service.ts:3291). The corpus showed financial_summary was 100% LLM-produced and never cross-checked (hollow, no amounts). The reconciler maps bills by role (final/interim/pharmacy/implant/sub-bill + discharge-slip fallback), picks a hospital anchor (final → interim → fallback), tallies pharmacy/implant separately (never silently folded), and emits a status — reconciled / single_source / discrepancy / no_financial_data — into validation_metadata.financial_reconciliation. It fills total_billed only when empty, never clobbers an LLM amount, and never blocks. When there's no money in the docs it says so (no_financial_data) rather than inventing a number.

5 · v2 vision-native pipeline harness-only — NOT in the production request path

The active re-architecture in Backend/src/Services/pipelineV2/. Design thesis (from types.ts): "the only LLM call in the whole pipeline is Stage 1's vision read" — Stages 0 & 2–7 are pure deterministic functions with no DB, no S3, no LLM, unit-tested on fixtures. A repo-wide grep confirms nothing outside pipelineV2/ imports it: today it is driven only by the benchmark harness (harness/runner.ts::runClaim).

Why v2 differs from production v1
  • One vision read replaces OCR→classify→extract — kills the garbled-OCR root cause; cheap-first / premium-escalation tiering.
  • Deterministic authority fusion replaces the LLM "mega-call" — Stage 5 is a pure FIELD_AUTHORITY ranking with auditable candidate trails, not one big non-deterministic prompt.
  • Advisory-only output — explicit two-layer ipd_doc/derived_page model + perceptual cross-doc dedup; no in-pipeline verdict.
Gated by the benchmark: a 15-patient hand-labelled corpus, a field-level scorer, and a regression baseline that hard-fails only on HIT→MISS. Replay mode is free; record makes real paid calls.

  • Cost API (costAccounting.service.ts): checkBudget (pre-flight, strictest dimension wins), recordCall (post-call insert, best-effort), getClaimSpendInr (SUM(cost_inr), fails closed → ∞). Hard cap CLAIM_HARD_LIMIT_INR=15, soft 10.
  • TOCTOU gap: checkBudget reads spend, the row is written after the call — concurrent sections on one claim can both pass the ₹15 check. The atomic reservation ledger (#31) is deferred (needs a migration).
  • LlmClient interface exposes only extract<T>() and classify() — "harmonise" / "pageRead" are task names routed through extract, not methods.
  • CRIT-2 fix: classify/extract/bundle previously called checkBudget but never recordCall, so getClaimSpendInr under-read and the cap was unenforceable. Each now records its spend.
  • Embeddings use a separate voyage-3 embedder (episodic memory), outside LlmClient.

9 · Where the code diverges from the written handoff verify before you trust a doc

  • Bundle classifier is text-only, not "one Claude-vision pass." Vision was disabled (page-mapping bug); it lives in the extractor instead.
  • Legacy-chain routing is triggered by OCR char count (>80k) / schema-fail / coverage-fail — not page count, not force re-runs.
  • Dedup is synchronous inside classifyBundle (+ belt-and-braces in the orchestrator & extractor) — it is not a queue/wave of its own.
  • Two decision surfaces, not one: rulesEngineV2 (episode, pure SQL) and adjudicationEngine (dossier, optional LLM).
  • actionEngine has no email channel — WhatsApp + in-app only.
  • v2 pipelineV2 is harness-only — zero production imports; the live path is still Wave-12 ingest → Wave-7 harmonise.
  • "Fix-18" is overloaded — a date-mirror block and the financial reconciler share the number.
  • Replay modes are live | record | replay (not "off"); cost gate has a real TOCTOU window pending #31.
  • CRIT-1/2/3 are fixed but not yet committed on this branch.
